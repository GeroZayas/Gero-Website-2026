Jinja2: Components in Different Directories

Golden Rule: render() always resolves paths relative to the loader roots, never the filesystem directly. Register all your template dirs in the loader, then use include/import with paths relative to those roots.

1. Tell Environment Where to Look (Multiple Dirs)

from jinja2 import Environment, FileSystemLoader

env = Environment(
    loader=FileSystemLoader([
        "templates",             # main templates
        "templates/components",  # partials/components
        "shared/templates",      # templates from another dir, even outside the project
    ])
)

The loader searches them in order; first match wins.

2. Use {% include %} or {% import %} in Any Template

base.html (in templates/):

<html>
<body>
  {% include "header.html" %}          {# found in templates/components/ #}
  {% block content %}{% endblock %}
  {% include "footer.html" %}
</body>
</html>

header.html (in templates/components/) — just plain HTML/vars:

<header><h1>{{ title }}</h1></header>

3. Variables and Context

{% include "header.html" %}   {# default: parent vars ARE visible #}

An included fragment sees the same variables as the template that includes it. No explicit passing needed.

4. Reusable "Functions": Macros

Want something callable with explicit arguments instead of a fragment? Use a macro:

templates/components/macros.html:

{% macro card(title, body) %}
  <div class="card"><h2>{{ title }}</h2><p>{{ body }}</p></div>
{% endmacro %}

Use it from any template:

{% from "macros.html" import card %}
{{ card("Hello", "Some text") }}

5. Rule of Thumb

Construct What it does When to use
{% include "file.html" %} Pastes a fragment (sees parent variables) Static/repeated chunks: header, footer
{% from "macros.html" import macro %} Calls a macro like a function (explicit args) Parameterized components: cards, buttons
{% extends "base.html" %} + {% block %} Inheritance: child fills blocks of a base Page layouts

6. Rendering

env.get_template("base.html").render(title="Home")  # not "templates/base.html"

Paths passed to get_template() / include / import are relative to the loader roots registered in FileSystemLoader, not to the project filesystem.

7. FastAPI: Same Jinja2, Wrapped

Con FastAPI es igual, solo cambia cómo se crea el entorno. FastAPI envuelve Jinja2 con Jinja2Templates:

Configurar la app (main.py)

from fastapi import FastAPI, Request
from fastapi.templating import Jinja2Templates

app = FastAPI()

# Caso simple: un solo directorio
templates = Jinja2Templates(directory="templates")

Para múltiples directorios, FileSystemLoader ya acepta una lista — no necesitas nada más:

from jinja2 import Environment, FileSystemLoader

templates = Jinja2Templates(
    env=Environment(loader=FileSystemLoader([
        "templates",              # páginas: base.html, index.html
        "templates/components",   # componentes: header.html, macros.html
    ]))
)

ChoiceLoader solo si mezclas tipos de loaders (filesystem + package + custom) o quieres prioridad entre grupos enteros. Con la lista simple de FileSystemLoader, la precedencia es archivo por archivo: mismo nombre en dos dirs → gana el dir que aparece primero en la lista.

# Caso avanzado: mezclar tipos de loaders
from jinja2 import ChoiceLoader, PackageLoader

env = Environment(loader=ChoiceLoader([
    FileSystemLoader("templates/overrides"),  # tus overrides primero
    PackageLoader("mi_app", "templates"),     # defaults de un paquete instalado
]))

Estructura típica

app/
├── main.py
└── templates/
    ├── base.html
    ├── index.html
    └── components/
        ├── header.html
        └── macros.html

Endpoint

@app.get("/")
def home(request: Request):
    return templates.TemplateResponse(
        request=request, name="index.html", context={"title": "Home"}
    )

Ojo: la ruta es relativa a los loader roots ("index.html", nunca "templates/index.html").

En las plantillas, igual que Jinja2 puro

{# templates/index.html #}
{% extends "base.html" %}
{% from "components/macros.html" import card %}

{% block content %}
  {% include "components/header.html" %}
  {{ card("Hola", "texto") }}
{% endblock %}

Nota: en FastAPI los includes/macro-imports funcionan idéntico a Jinja2 puro. La única diferencia FastAPI-specific es el request en el contexto — disponible automáticamente en todas las plantillas, incluidos los includes.

Summary

  • Multiple paths in the loader → Jinja searches them in order.
  • {% include %} = paste a fragment (parent context visible).
  • {% import %}/{% from %} = call macros like functions (explicit args).
  • Always reference templates by path relative to the loader roots.
  • FastAPI: Jinja2Templates(env=Environment(loader=FileSystemLoader(["dir1", "dir2"]))) para múltiples dirs; TemplateResponse(request=request, name=..., context=...) en los endpoints.
  • ChoiceLoader solo para mezclar tipos de loaders distintos (filesystem + package + custom).
