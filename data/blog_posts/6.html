TIL git --word-diff

git diff --word-diff shows inline, word-level changes instead of line-level diffs.

Think of it as “diff, but with a scalpel instead of a chainsaw.”

What it does

  • Compares files word by word
  • Highlights added and removed words inline
  • Ideal for prose, docs, comments, or small code edits

Example

git diff --word-diff

Output style (simplified):

This is [-old-]{+new+} text.
  • [-old-] → removed
  • {+new+} → added

Common variants

git diff --word-diff=color

Same thing, but colorized (much nicer).

git diff --word-diff-regex='[^[:space:]]+'

Defines what a “word” is (useful for code tokens).

git diff --word-diff=plain

Explicit plain-text markers (default behavior).

When to use it

  • Reviewing documentation
  • Reviewing comments
  • Catching tiny semantic changes hidden in big lines
  • Code reviews where whitespace noise is killing your soul

When not to use it

  • Large refactors
  • Reformatting changes
  • Anything where line structure matters more than tokens

TL;DR: git diff --word-diff is precision diffing. Use it when lines are too coarse and you care about what changed, not just where.
